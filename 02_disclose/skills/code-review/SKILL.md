# Code Review 절차

## 목표
코드를 고쳐 쓰는 게 아니다 — 심각도 순으로 "무엇이·왜 문제인지"를 보고하는 것이다.

## 단계
1. 대상 코드를 끝까지 읽고 의도를 한 문장으로 파악한다 — 의도를 모르면 리뷰하지 않는다.
2. `checklists/review-checklist.md`(L3 리소스)를 읽어 기준을 적용한다.
3. 문제를 보안 → 정확성 → 성능 → 가독성 순으로 찾는다 — 이 순서가 보고서 순서다.
4. 문제마다 `[심각도] 위치 — 설명 — 수정 제안` 한 줄로 적는다.
   - 위치: 함수명 또는 행 번호
   - 설명: 왜 문제인지 한 문장
   - 제안: 구체적 수정 방법 (짧은 코드 스니펫 가능)

## 심각도 기준
- `critical`: 보안 취약점·데이터 손상 가능 (키 노출, eval, 인젝션)
- `major`: 오동작·자원 누수 (예외 삼킴, 미해제, 경계값 미처리)
- `minor`: 스타일·가독성 (변수명, 매직 넘버, 함수 책임 과다)

## 출력 형식
- 문제 목록만 출력한다 — 인사말·서두·총평은 적지 않는다.
- 문제가 없으면 `이상 없음`이라고만 답한다 — 억지로 만들지 않는다.
